# 语义组件不是换主题色：四个行业场景的信息设计

很多“AI 生成 UI”演示会把一段内容装进卡片，然后根据场景切换蓝色、绿色或红色。它看起来
比普通 Markdown 丰富，却没有真正改善用户理解信息的方式。

医疗检验、田间观测、设备点检和安全调查面对的任务完全不同。真正的行业语义组件，应该先
回答“用户要做什么判断”，再决定信息层级、组件结构和视觉语言。

Semantic Markdown 的行业示例刻意使用四套不同的信息设计，而不是一张万能卡片的四个
主题色。

## 先把三层职责分开

一个语义节点从模型到界面，至少经过三层：

### Protocol：定义事实和约束

Protocol 声明模型可以表达哪些业务字段、何时允许使用节点，以及哪些内容不能推断。它不
负责像素、颜色或布局。

### 业务组件：定义信息结构和交互

React/Vue 组件决定标题、读数、单位、元数据、证据和操作如何组织，也负责可访问性、键盘
行为与宿主 Action。

### 视觉系统：定义品牌和场景语言

CSS 或设计系统负责字体、间距、材质、响应式布局和状态反馈。视觉变化来自可信应用状态，
而不是模型注入的 `style` 或 `class`。

```text
模型事实 → Protocol → 可信属性 → 业务组件 → 设计系统
```

如果把三层混在一起，模型就会开始决定页面长什么样，组件则不得不猜测属性是否安全。

## 场景一：医疗检验不是一张“红色警告卡”

医疗场景使用 `clinicalResult`：

```md
:::clinicalResult{test="糖化血红蛋白" value=7.2 unit="%" reference="4.0–6.0" flag="high" collectedAt="2026-08-16 08:30"}
该指标高于本次报告参考区间，建议结合既往趋势由专业人员复核。
:::
```

Protocol 要求保留：

- 检验项目。
- 测量值与单位。
- 报告给出的参考区间。
- normal/high/low 标记。
- 采样时间。

组件的首要任务不是“强调异常”，而是让用户把数值、单位、参考区间和时间放在一起阅读。
因此示例采用类似检验单的结构：项目名称和采样时间位于 Header，数值与单位形成主要读数，
参考区间与结果标记组成定义列表，解释文字位于独立 Note 区域。

Protocol 还明确约束：不能把教育性解释写成诊断或治疗建议，不能脱离报告参考区间自行判断
flag。

即使使用颜色表达 high/low，也必须同时显示文字和参考区间。单纯把背景变红既不够准确，
也不利于色觉差异用户。

## 场景二：农业观测关注地块、阶段和操作窗口

农业场景使用 `fieldObservation`：

```md
:::fieldObservation{field="东区 3 号地" crop="冬小麦" stage="灌浆期" soilMoisture=18 condition="watch" observedAt="2026-08-18 06:40"}
表层墒情偏低，建议复核未来降水后安排灌溉窗口。
:::
```

这里最重要的不是一条抽象的“18%”，而是：哪个地块、什么作物、处于哪个生育阶段、何时
观测，以及当前是适宜、观察还是立即处理。

示例组件因此更像田间记录：

- Header 强调地块与观测时间。
- 作物和生育期组合展示。
- 土壤含水率使用仪表式读数，但同时保留精确数字。
- condition 使用“墒情适宜/持续观察/立即处理”等操作语言。
- 子 Markdown 解释现场影响和下一次检查动作。

Protocol 限制土壤含水率必须为 0 到 100 的实测百分比，`urgent` 只能来自明确的现场判断，
不能把天气预报伪装成已经发生的田间观测。

这说明一个行业节点不仅约束格式，也应该约束事实来源。

## 场景三：制造点检需要设备语境和处置状态

制造场景使用 `machineInspection`：

```md
:::machineInspection{asset="CNC-102" line="A-03" reading=86 unit="°C" state="attention" checkedAt="2026-08-18 14:20"}
主轴温度高于班组关注线，需检查冷却液循环。
:::
```

设备点检用户通常需要快速回答：是哪台设备、位于哪条线、测量值是什么、何时检查、现在能否
继续运行。

示例使用工业铭牌式结构：

- `ASSET / CNC-102` 作为稳定标识。
- `RUN / CHECK / LOCKOUT` 同时使用文字、结构和视觉状态。
- 读数和单位占据主视觉区域。
- 生产线与点检时间使用紧凑定义列表。
- 处置说明保持独立，避免与测量事实混淆。

Protocol 不允许模型凭空创造设备阈值，也不能为了强调而把 `attention` 升级成 `stop`。
如果源材料只说明“需要观察”，界面就不应该擅自显示 LOCKOUT。

这里的核心不是工业风 CSS，而是把“测量事实”和“操作状态”放在正确的位置。

## 场景四：安全调查必须区分证据与结论

安全场景使用 `threatFinding`：

```md
:::threatFinding{incidentId="IR-2026-0819" severity="high" phase="lateral-movement" asset="prod-db-07" observedAt="2026-08-19 02:14 CST"}
检测到异常服务账号访问，相关凭据已轮换并隔离源主机。
:::
```

安全调查界面需要让分析人员快速定位：

- 事件 ID。
- 严重等级。
- 当前攻击阶段。
- 涉及资产。
- 带时区的观测时间。
- 已观察证据与当前遏制动作。

示例采用调查终端和证据链式布局：Header 同时展示事件编号和等级，phase/asset/time 作为
结构化元数据，正文位于 Evidence 区域。

Protocol 要求只使用证据已经建立的 severity 和 phase，明确区分“异常观测”与“确认失陷”，
也不能编造 IOC。因为在安全场景里，视觉上更紧张的卡片并不代表结论更可靠。

## 四种组件真正不同在哪里

| 场景 | 首要判断 | 主信息结构 | 必须避免 |
|---|---|---|---|
| 医疗 | 数值是否超出报告参考区间 | 检验项、数值、单位、区间、采样时间 | 自动诊断和治疗建议 |
| 农业 | 哪个地块在什么阶段需要何种操作 | 地块、作物阶段、实测墒情、观测时间 | 把预测当作现场观测 |
| 制造 | 哪台设备能否继续运行 | 设备、产线、读数、状态、处置 | 编造阈值或擅自停机 |
| 安全 | 当前证据支持什么调查结论 | 事件、阶段、资产、时间、证据 | 把异常等同于确认失陷 |

如果四种场景只是换颜色，这些差异不会进入 UI，也不会进入模型约束。

## 状态不能只靠颜色

Semantic Component 应该把状态表达为多重信号：

- 文本：`高于参考值`、`持续观察`、`LOCKOUT`、`high`。
- 结构：状态放在 Header、读数旁或操作区。
- 图形：箭头、仪表、斜纹、标签轮廓。
- 颜色：作为增强，而不是唯一载体。
- ARIA 和语义 HTML：保证辅助技术能理解内容。

同样，Pending 也不必用闪烁动画。可以通过轻微透明度、骨架边界或 `data-status` 告知用户
内容仍在生成，同时避免让正在阅读的卡片剧烈跳动。

## 模型不应该控制布局

为了让模型“更灵活”，很容易向 Protocol 增加：

```text
color
background
columns
size
className
style
```

这会把业务语义重新退化成低层视觉指令，也扩大安全和兼容成本。

更好的做法是让可信宿主根据场景控制整份文档：

```tsx
<section data-scene="manufacturing">
  <SemanticMarkdown ... />
</section>
```

模型只输出 `machineInspection` 的业务事实，应用根据当前产品模块选择工业设计系统。历史
内容换主题、品牌升级或响应式重排时，不需要让模型重新生成。

## 如何设计一个新的行业节点

可以使用下面的顺序：

1. 写出用户看到这条信息后必须完成的判断。
2. 列出判断所需的最小事实字段。
3. 标记哪些字段必须来自原始资料，不能由模型推断。
4. 定义普通文本 Fallback 时仍必须保留的内容。
5. 选择 Inline、Block 或 Container。
6. 设计信息结构和可访问性，再设计视觉风格。
7. 用真实、错误、缺失、Pending 和窄屏状态共同测试。

不要从“我想做一张漂亮卡片”开始。好的语义组件首先是一种信息模型，其次才是一种视觉
表现。

## 结语

Semantic Markdown 的价值不在于让每段 AI 回答都变成卡片，而在于准确识别那些值得被
结构化的业务事实，并把它们交给真正理解任务的组件。

医疗组件帮助比较数值与参考区间，农业组件帮助安排现场操作，制造组件帮助识别设备状态，
安全组件帮助区分证据与结论。它们的差异来自任务和信息层级，不是来自四套配色。

当 Protocol、组件和视觉系统各自守住边界，AI 可以输出丰富的行业内容，而产品团队仍然
掌握最终的信息质量、可访问性、品牌和操作权限。
